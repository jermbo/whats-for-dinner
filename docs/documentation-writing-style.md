# Writing style

A page must teach a reader who knows nothing about the project. This page tells how to write such a page.

## The order of an explanation

1. **The problem.** Start with the question that the reader has. "A store is a bad place to type."
2. **The mechanism.** Tell how it works, one step at a time.
3. **The reason.** For each rule, tell why. "A price changes, so each purchase keeps its price."
4. **An example.** Use real names and real numbers: rice, 1000 g, 2.49. One example that continues through a topic is better than many.

## Teach, do not list

| Not this                                              | But this                                                                                                           |
| ----------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------ |
| The full row is the button. There is no number field. | You use this screen with one hand, between the shelves. So each action is one tap, and nothing needs the keyboard. |
| The photo is resized on the client.                   | The app draws the image on a small canvas. This step is where the photo becomes small.                             |

The left side gives facts. The right side gives the reader a picture and a reason.

## The language

The pages use Simplified Technical English (ASD-STE100).

- Write short sentences: 20 words or less for a step, 25 or less for a description.
- Put one idea in one sentence.
- Use the active voice and the present tense. "The app makes the row", not "the row is made".
- Speak to the reader as "you".
- Use simple words. Explain a technical word at its first use: "a blob: a block of bytes with a type".
- Use one word for one thing, each time. Each topic has a glossary for this, such as the [shopping glossary](shopping/glossary.md).

## Headings

A heading tells what the section says: "Why the photo is too large". Do not use "Overview", "Details", or "Notes".

## What a page does not have

- No status, no plan, and no comparison with the code of today.
- No labels for the source of a fact.
- No "see above" and no "as mentioned". Each page stands alone.
